# 공부 노트 — vpc-web 미션

## 한 장 그림 (내 노트북 시점)

```
내 노트북 ── 인터넷 ── IGW ── VPC
                              └ 서브넷 ── [라우팅 테이블: 0.0.0.0/0 → igw]
                                  └ EC2 (퍼블릭 IP)
                                      └ Nginx
```

| 부품 | 무엇인가 | 이 미션에서 하는 일 |
|---|---|---|
| VPC | AWS 안의 내 네트워크 전체 | 모든 부품을 담는 큰 상자 |
| 서브넷 | VPC를 나눈 구역 하나(한 가용 영역) | 같은 규칙(라우팅 테이블, 퍼블릭 IP 자동 할당)을 쓰는 서버 묶음 |
| 라우팅 테이블 | "받는 주소가 이 범위면 → 저기로 넘겨라" 표 | 서브넷에 연결돼서, 서브넷에서 **나가는** 꾸러미의 길을 정함 |
| IGW(인터넷 게이트웨이) | VPC와 인터넷 사이 출입구 | VPC에 연결(Attach) |
| EC2 | AWS가 빌려주는 가상 컴퓨터 | 여기서 Nginx가 돌며 웹페이지를 응답 |
| 퍼블릭 IP | 인터넷에서 서버를 부르는 주소 | 직접 만든 서브넷에서는 **저절로 안 생김** → EC2 띄울 때 "자동 할당: 활성화" |

**한 줄**: VPC는 내 네트워크, 서브넷은 같은 규칙을 쓰는 구역, EC2는 그 구역의 컴퓨터, Nginx는 그 컴퓨터에서 도는 프로그램.

## 인터넷과 오가려면 세 칸이 모두 있어야 한다

| 칸 | 켜는 곳 | 확인하는 곳 |
|---|---|---|
| ① IGW | IGW 화면 → 작업 → VPC에 연결 | IGW 상태 `Attached` |
| ② `0.0.0.0/0 → igw` 줄 | 라우팅 테이블 → 라우팅 편집 → 추가 + **서브넷 연결 편집** | 서브넷 화면의 '라우팅 테이블' 탭 |
| ③ 퍼블릭 IP | EC2 띄울 때 "퍼블릭 IP 자동 할당" (또는 서브넷 설정) | EC2 화면의 '퍼블릭 IPv4 주소' 칸 |

하나라도 빠지면 브라우저에 **"응답 시간 초과"**.

## 큰 그림: 요청과 응답

```
① 요청  "페이지 줘"
 [내 노트북]          [인터넷]         [AWS ─ 여기부터 내가 설정]
  브라우저  ─────▶  (오가는 길)  ─▶  IGW ─▶ 보안그룹 ─▶ EC2 ─▶ Nginx
                   퍼블릭 IP로       들어오는 문  들어와도 되나?

② 응답  "여기 페이지"
  브라우저  ◀─────  (오가는 길)  ◀─  IGW ◀─ 라우팅 테이블 ◀─ EC2 ◀─ Nginx
                                  나가는 문  0.0.0.0/0 → igw
```

- 브라우저: 노트북 안에서 요청을 만드는 프로그램
- 인터넷: 노트북과 AWS 사이의 길(공유기, 통신사…). 내가 설정할 것 없음

## 포트는 문

- IP 주소로 **컴퓨터**를, 포트 번호로 그 안의 **프로그램**을 찾는다 (80번 = Nginx)
- 요청 겉봉: 보내는 곳 = 노트북의 임시 번호 / 받는 곳 = 서버 80번. 응답은 두 번호의 자리가 뒤바뀐다
- 겉봉의 80은 **가고 싶은 문 번호**(누구나 적을 수 있음). 통과 여부는 **보안그룹 규칙**(어느 문 + 어디서 왔나)이 정한다
- 응답은 보안그룹이 "아까 들여보낸 요청의 답장"으로 기억해서 내보낸다
- 진짜 열쇠는 SSH 키 페어(.pem)

## 포트는 어디서 보나

| 포트를 보는 곳 | 포트를 안 보는 곳 |
|---|---|
| 요청 꾸러미(80번으로), 보안그룹(80번 통과), Nginx(80번에서 기다림) | 인터넷, IGW, 라우팅 테이블(주소만 봄) |

포트는 문 앞(보안그룹, Nginx)에서만 따지고, 길(인터넷, IGW, 라우팅 테이블)은 주소만 본다. 세 곳의 숫자가 모두 80으로 맞아야 페이지가 뜬다.

## AWS와 VPC는 다르다

```
AWS (클라우드 전체)
 └ 서울 리전
     └ 내 계정
         ├ VPC (내가 만든 것, 이번 미션)
         │   └ 서브넷 └ EC2(보안그룹이 붙음) └ Nginx
         └ 기본 VPC (가입 때 자동으로 생김)
```

IGW는 VPC 안이 아니라 VPC 경계에 붙은 출입문.

## 한 번 접속에는 두 방향이 있다

```
① 요청:  내 노트북 ──▶ 인터넷 ──▶ igw ──▶ 웹 서버   (퍼블릭 IP로 찾아옴)
② 응답:  내 노트북 ◀── 인터넷 ◀── igw ◀── 웹 서버   (서브넷 라우팅 테이블 0.0.0.0/0 → igw로 나감)
```

### 칸마다 맡은 방향

| 칸 | ① 요청 | ② 응답 |
|---|---|---|
| 퍼블릭 IP | 서버를 찾는 주소 | — |
| IGW | 들어오는 문 | 나가는 문 |
| 보안그룹 | 들여보낼지 결정 | — |
| 라우팅 테이블 | — | 나갈 길 안내 |
| Nginx | 요청을 받음 | 페이지를 보냄 |

요청은 퍼블릭 IP로 찾아와 보안그룹을 통과하고, 응답은 라우팅 테이블을 따라 IGW로 나간다.

## 라우팅 테이블 읽는 법

- **Destination** = 꾸러미가 가려는 목적지 주소(의 범위)
- **Target** = 거기 가려면 먼저 들러야 할 곳
- 줄은 **내가** 적고, 그 줄대로 넘기는 건 AWS가 자동으로
- 맞는 줄이 없으면 꾸러미는 버려진다
- `0.0.0.0/0` = 모든 주소. 응답을 누구에게 보낼지 미리 모르니까
- 더 좁게 맞는 줄이 이긴다 (VPC 안 주소는 `local`로)

## 안 될 때 점검 순서 (서버에서 거슬러 가기)

1. EC2에 퍼블릭 IP가 있나
2. EC2 → 서브넷으로 이동
3. 서브넷의 '라우팅 테이블' 탭에 보이는 표 = 실제로 쓰는 표
4. 그 표에 `0.0.0.0/0 → igw` 줄이 있나
5. 그 igw가 같은 VPC에 Attached인가

## 오늘(11/17) 물어본 것

| 물어본 것 | 답 |
|---|---|
| 패킷이 뭐지? | 네트워크로 보내는 작은 꾸러미. 겉봉(보내는 주소, 받는 주소, 포트) + 내용물 |
| 라우팅 테이블과 보안그룹 차이? | 보안그룹 = 겉봉의 보내는 주소·포트를 보고 **들여보낼까**. 라우팅 테이블 = 받는 주소를 보고 **어디로 넘길까** |
| 표를 새로 만들면 바로 쓰이나? | 아니다. **서브넷에 연결**해야 쓰인다. 연결 안 하면 기본 표를 씀 |
| 라우팅 테이블은 EC2 안에 있나? | VPC에 있고 서브넷에 연결. 그 서브넷의 EC2는 모두 같은 표를 따름 |
| 실무에선 Destination·Target을 어떻게 정하나? | "이 서버가 어디와 통신하나?" 웹 서버는 퍼블릭 패턴(`0.0.0.0/0 → igw`), DB는 프라이빗(NAT, 유료) |
| 설계값은 외워야 하나? | 아니다. 설계표에 적어 두고 보면서 콘솔에 옮긴다 |
