## 2026-11-18 일부러 끊어 보기 (라우팅 줄 삭제 실험)

| 확인 | 예측 | 실제 |
|---|---|---|
| 브라우저 새로고침 | 안 됨 | 시간 초과 (ERR_CONNECTION_TIMED_OUT) — [스크린샷](images/exp-02-browser-timed-out.png) |
| 열어 둔 SSH 창에서 엔터 | 안 나옴 | 멈춘 뒤 `Operation timed out`, 연결 끊김. 줄 복구 뒤에도 되살아나지 않음 — [스크린샷](images/exp-01-open-ssh-timed-out.png) |
| 새 SSH 접속 | 안 됨 | 시간 초과 |
| 줄 복구 뒤 | — | 브라우저 Nginx 페이지, 새 SSH 접속 성공 — [브라우저](images/exp-03-browser-restored.png), [SSH](images/exp-04-new-ssh-restored.png) |

정리: 라우팅 줄에는 목적지와 타겟만 있고 포트가 없다. 그래서 길이 빠지면 80과 22가 함께, 모두 시간 초과가 된다. 거부(즉시)가 아니라 시간 초과인 것은 패킷이 버려질 뿐 아무도 거절 답장을 보내지 않기 때문이다.

## 2026-11-19 집에서 SSH만 시간 초과

| 시각 | 단계 | 내용 |
|---|---|---|
| 16:48 | 증상 | EC2 다시 시작 후 집 랩탑에서 브라우저 `http://새IP`는 Nginx 열림, `ssh`는 `Connection timed out` (port 22) — [스크린샷](images/trouble-04-ssh-timeout-from-home.png) |
| 16:50 | 가설 1 | 키 파일을 나중에 설정해서 생긴 SSH 인증 문제 |
| 16:50 | 검증 1 | 키가 틀리면 서버가 `Permission denied (publickey)`로 **대답**한다. 지금은 대답 없는 시간 초과 → 요청이 EC2 안 SSH 프로그램까지 못 감 → 가설 1 기각 |
| 16:51 | 가설 2 | 80은 되고 22만 안 됨 → 길은 멀쩡(①-4). 포트별로 갈리는 곳 중 대답 없이 버리는 곳 = 보안그룹 22번 줄 |
| 16:52 | 검증 2 | 22번 줄 소스 = 11-18 학습장에서 넣은 IP. 오늘 출발지 = 집 IP → 맞는 줄 없음 |
| 16:55 | 조치 | 22번 소스를 '내 IP'(집 IP)/32로 교체 (0.0.0.0/0으로 넓히지 않음) |
| 16:58 | 결과 | SSH 접속 성공. 호스트 지문이 11-18과 같음 → IP는 바뀌었어도 같은 서버 |
| | 재발 방지 | 장소를 옮겨 접속하기 전에 22번 소스를 그때 IP로 바꾸고 README 기록표에 시각과 함께 적는다 |

## 2026-11-19 일부러 막아 보기 2: 보안그룹 80번 줄 삭제

| 확인 | 예측 | 실제 |
|---|---|---|
| 새 시크릿 창 브라우저 | 안 됨 | 시간 초과 — [스크린샷](images/exp-05-sg80-deleted-browser-timeout.png) |
| 열어 둔 SSH에서 `ls` | 안 됨 | 됨(프롬프트 바로 돌아옴) — [스크린샷](images/exp-06-sg80-deleted-ssh-alive.png) |

정리: 보안그룹 줄은 포트마다 따로라 80번만 막힌다. localhost는 EC2가 자기 자신에게 보내는 요청이라 보안그룹을 지나지 않는다.

## 증상 지문 표 (어느 칸이 막았나)

| 막힌 곳 | 무엇을 거르나 | 증상이 보이는 곳·모양 | 가장 작은 고침 |
|---|---|---|---|
| 길 (라우팅 줄·IGW·퍼블릭 IP) | 포트 구분 없이 그 서버의 모든 통신 | 브라우저·SSH **전부** 시간 초과 | 빠진 칸 하나 채우기 (예: `0.0.0.0/0 → IGW`) |
| 보안그룹 | 들어오는 패킷 (포트, 보낸 곳) | **그 포트만** 시간 초과, 다른 포트는 됨 | 그 포트 줄 하나 고치기 (예: 22 소스를 지금 IP로) |
| 서버 프로그램 (Nginx) | 그 포트를 듣는 프로그램이 있나 | **즉시 거부** (connection refused) | 프로그램 설치·시작 |
| IAM | 사람의 AWS 작업 (누가, 어떤 Action) | **콘솔 빨간 배너**에 Action 이름 (예: `s3:CreateBucket`) | 정책에 그 Action 한 줄 더하기 (필요할 때만) |

판단 순서: "되는 게 하나라도 있나?" 없으면 길, 있으면 안 되는 포트의 문. 콘솔 배너에 작업 이름이 나오면 IAM.
