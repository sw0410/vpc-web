# 트러블슈팅 (vpc-web)

실습 중 실제로 겪은 장애 두 건입니다. 시각별 원본 메모는 [troubleshooting-notes.md](troubleshooting-notes.md)에 있습니다.

## 사례 1. 브라우저와 SSH가 모두 시간 초과 (2026-11-18)

| 단계 | 내용 |
|---|---|
| 증상 | SSH도 브라우저도 휴대폰 LTE도 모두 `시간 초과` |
| 가설 | 보안그룹 22번 소스가 틀렸다 / 내 쪽 네트워크 문제다 / AWS 네트워크 설정(라우팅 테이블, IGW, 퍼블릭 IP)이 빠졌다 |
| 검증 | 내 IP가 22번 소스와 같고 80번은 누구나 허용인데도 웹이 막힘 → 보안그룹 아님. 휴대폰 LTE도 막힘 → 내 쪽 아님. 서브넷 라우팅 테이블에 `10.0.0.0/16 → local` 한 줄뿐 ([화면](images/trouble-01-route-table-missing-igw.png)) |
| 조치 | `0.0.0.0/0 → IGW` 줄 추가 후 **변경 사항 저장** ([화면](images/trouble-02-route-table-fixed.png)) |
| 결과 | SSH 접속 성공, 브라우저는 즉시 `연결 거부`(Nginx 설치 전이라 정상) ([화면](images/trouble-03-browser-refused-before-nginx.png)) |
| 재발 방지 | 전날 줄을 넣고 저장을 누르지 않은 것이 원인. 설정 뒤에는 편집 화면이 아니라 적용된 화면에서 확인한다 |

## 사례 2. 집에서 SSH만 시간 초과 (2026-11-19)

| 단계 | 내용 |
|---|---|
| 증상 | 같은 IP `43.200.2.228`로 브라우저는 Nginx 페이지가 뜨는데 ([화면](images/13-browser-after-restart.png)) SSH만 `Connection timed out` ([화면](images/trouble-04-ssh-timeout-from-home.png)) |
| 가설 | 키 문제다 / 보안그룹 22번 줄이 지금 위치를 허용하지 않는다 |
| 검증 | 키가 틀리면 `Permission denied (publickey)`로 대답이 온다. 대답 없는 시간 초과라 키 아님. 웹은 되므로 라우팅·IGW는 정상. 22번 소스 = 전날 학습장 IP, 지금 = 집 IP |
| 조치 | 22번 소스를 현재 랩탑 IP `/32`로 교체 (`0.0.0.0/0`으로 넓히지 않음). 교체 화면은 캡처하지 못했고 리소스를 삭제해 다시 찍을 수 없음 |
| 결과 | 랩탑 터미널에서 SSH 접속 성공, `ubuntu@ip-10-0-1-7` 프롬프트에서 명령 실행 ([화면](images/exp-06-sg80-deleted-ssh-alive.png), 같은 날 이어서 한 실험 중 캡처) |
| 재발 방지 | 접속 장소가 바뀌면 22번 소스를 현재 기기의 IP로 바꾸고 기록한다 |

## 증상으로 원인 찾기

| 증상 | 먼저 볼 곳 |
|---|---|
| 브라우저·SSH **모두** 시간 초과 | 라우팅 테이블, IGW, 퍼블릭 IP (포트를 보지 않는 곳) |
| **한 포트만** 시간 초과 | 그 포트의 보안그룹 인바운드 줄 |
| **즉시** 연결 거부 | EC2 안의 프로그램 (Nginx 실행 여부) |
| `Permission denied` | 키 또는 EC2 안 권한 (`sudo`) |
| 콘솔 빨간 배너 | IAM 정책 |

시간 초과는 패킷이 중간에 버려져 아무도 대답하지 않았다는 뜻이고, 거부나 `Permission denied`는 서버까지 도착해서 대답이 왔다는 뜻입니다.
